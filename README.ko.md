RealTrace는 인간의 창작임을 증명하는 **현장 증명 시스템**이다. 암호 서명 체인으로 어떤 콘텐츠가 "정말 인간이 실시간으로 쓴 것"임을 증명한다——AI가 생성한 것도, 나중에 붙여 넣은 것도, 변경된 것도 아니다.

```text
인간의 창작 ── 실시간 스탬프 ── 서명 체인 ── 봉인·상장 ── 검증 가능 · 추적 가능 · 위조 불가
```

## 선언

2022년 11월, ChatGPT가 태어났다. 그날부터 모든 것이 위조될 수 있는 세상에서, "진짜"는 사치품이 되었다.

AI는 어떤 스타일도 흉내 낼 수 있다——하지만 당신이 타이핑한 시간만은 위조할 수 없다. 탐지기는 추측한다. RealTrace는 증명한다.

RealTrace는 인간의 창작임을 증명하는 **현장 증명 시스템**이다. 첫 글자를 두드리는 순간부터, 멈춤 하나, 삭제의 흔적, 타자의 리듬까지 모두 실시간으로 기록되어 Ed25519 서명으로 위조할 수 없는 창작 체인에 묶인다. 글을 마치면 당신은 `.rt` 체인 파일을 손에 쥔다——검증 가능, 추적 가능, 위조 불가.

**이것은 더 이상 선택 문제가 아니다.** 모든 봉인은 바로 앞 봉인의 해시를 참조한다. 인과의 순서는 암호 기술로 고정되고, 사후 수정은 수학적으로 검출된다. 이것은 통계 모델의 추측이 아니라, 물리와 수학이 준 증거다.

**당신은 창작자다. 증거를 가질 자격이 있다.** "이거 AI가 쓴 거 아니야?"라는 의심을 받았을 때, 변명만으로 넘어가선 안 된다. RealTrace는 독립적으로 검증할 수 있는 현장 증명을 준다——투고에도, 권리 주장에도, 입증에도. 창작자는 맨손으로 싸우면 안 된다.

**당신의 콘텐츠는, 영원히 당신의 것이다.** 본문은 절대 기기를 떠나지 않는다. 체인에 기록되는 것은 해시와 행동 특징뿐이다. 우리는 "프라이버시를 지킵니다"라고 약속하지 않는다——구조상 콘텐츠에 닿을 수 없기 때문이다. 스탬프 찍기, 검증, 증명서 확인 모두 오프라인으로 완결된다. 사이트가 닫혀도 체인은 살아 있다.

**신뢰는, 플랫폼이 스스로 정할 일이 아니다.** 하위 체인의 루트 해시는 공식 창세 체인에 앵커링된다. 어느 플랫폼에서 서명된 체인이든, 같은 공개 앵커까지 거슬러 올라가 독립적으로 감사할 수 있다.

RealTrace는 오픈소스다. 개인은 무료. 모든 창작자가 자신의 작품에 봉인을 찍을 수 있다.

**당신의 창작. 당신의 현장 증명.**

## 인간의 창작이 '사재기'되기 시작했다

2026년 7월, 법원이 봉인을 해제한 문서가 Anthropic의 '파나마 프로젝트(Project Panama)'의 실체를 드러냈다. 중고 서적상을 통해 실물 헌책 100만 권 이상을 대량 매입하고, 유압 프레스로 책등을 잘라 내고, 한 장씩 스캔한 뒤 원본을 폐기했다. 단지 Claude가 '사람이 직접 쓴 글자'를 더 많이 읽게 하기 위해서였다. 또 다른 사건에서는 무단으로 약 700만 권의 도서가 학습에 사용됐고, 15억 달러에 합의하며 미국 저작권 소송 사상 최대 기록을 세웠다.

AI 기업들이 인간의 창작을 사재기하고 있다. 그들은 누구보다 잘 알고 있기 때문이다. 모델은 무한히 생성할 수 있지만, 인간의 사고·경험·선택은 유한하다는 것을. 헌책은 사들여지고, 스캔되고, 폐기된다. 그 사이에 새로운 세대가 써 내려간 글은 AI의 홍수에 묻혀 '이건 내가 쓴 거야'라고 증명조차 할 수 없게 된다.

인간의 창작이 희소한 자원이 된다면, 그것은 증명되고 지켜져야 한다.

RealTrace가 하는 일이 바로 이것이다. 첫 글자를 쓰는 순간부터, 창작의 과정을 검증 가능하고 변조 불가능한 서명 체인에 잠근다. 당신의 글은 언제나 당신의 것이다. 당신의 창작에는 현장 증명이 있다.

**인간의 창작이 희귀해지는 시대, RealTrace가 바로 그 증명이다.**

## 왜 RealTrace인가

2022년 11월, ChatGPT가 태어났다. 그날부터 인터넷 위의 모든 것이 "신뢰할 수 없는" 것이 되었다: 뉴스, 댓글, 논문, 시, 코드, 계약서, 소장——작가 자신조차, 어떤 글이 사람의 것인지 기계의 것인지 육안으로 분간할 수 없게 되었다.

"AI가 글을 쓸 수 있다"보다 더 무서운 것은, **모든 것이 위조될 수 있을 때 진짜가 사치품이 된다**는 것이다. 인간 창작의 가치는 소리 없이 희석된다——당신의 생각, 감정, 경험, 선택이 기계 출력과 구분할 수 없는 텍스트가 되어 간다.

RealTrace가 하려는 것은, "인간의 창작"에 암호학적 **현장 증명**을 주는 것이다:

- **첫 글자를 쓰는 순간부터**: "이건 내가 썼다"는 사후 주장이 아니라, 창작 과정을 실시간으로 기록하고 실시간으로 서명한다;
- **플랫폼의 평판에 의존하지 않는다**: 모든 서명은 오프라인에서 독립적으로 검증할 수 있고, 수학적으로 감사 가능하다;
- **콘텐츠 미업로드**: 본문은 항상 당신 손에. 체인에는 해시와 행동 특징만 기록된다.

> AI가 모든 것을 모방할 수 있는 시대에, 인간 창작의 존엄은 지켜질 가치가 있다.

## 우리가 해결하는 문제

| 문제 | RealTrace의 해결책 |
|:--|:--|
| AI 생성 콘텐츠와 인간 창작을 구분할 수 없다 | 실시간 스탬프: 작성 중 Ed25519 서명 스탬프를 자동 생성하고 타자 리듬·멈춤·삭제량 등의 행동 특징을 기록 |
| 사후 변조·교체를 감지할 수 없다 | 체인 해시: 각 스탬프가 바로 앞 스탬프의 해시를 참조하여, 사후 수정은 수학적으로 검출 가능 |
| 콘텐츠 업로드는 프라이버시 위험 | 콘텐츠 미업로드: 본문은 로컬에만. 체인에는 콘텐츠 해시와 행동 특징만 기록 |
| 검증이 서버에 의존하여, 폐쇄되면 무효 | 완전 오프라인: 스탬프·검증·증명서 확인 모두 로컬에서 완결. `.rt` 파일은 자체 완결 |
| "누가 서명했는지·어느 버전인지"를 추적할 수 없다 | 창세 체인 앵커링: 하위 체인 루트 해시를 공식 창세 체인에 제출하고, 버전을 체인과 함께 기록하여 공개 감사 가능 |

## 핵심 원리

**서명 체인(스탬프 체인)**——작성 중의 모든 봉인이 서명 체인 위의 노드가 된다:

```text
chainHash = SHA-256(sessionId || index || salt || timestamp || contentHash || prevChainHash || nonce)
signature = Ed25519_sign(chainHash)
```

- **인과 순서는 위조할 수 없다**: 각 스탬프의 해시가 바로 앞 스탬프를 참조하고, 체인의 위상 순서는 `prevChainHash`로 결정된다. 시스템 시간과 무관하며, 사후 삽입·재배열은 불가능;
- **개인 키는 위조할 수 없다**: Ed25519 서명은 로컬에서 생성된 개인 키로 이루어지며, 개인 키는 기기를 떠나지 않는다;
- **행동 지문**: 각 스탬프에 타자 리듬 / 멈춤 / 삭제량 특징(HMAC 행동 체인)을 첨부하여 신뢰도 분석에 사용;
- **창세 체인 앵커링**: 하위 체인 키는 공식 시드에서 HKDF-SHA256으로 결정적으로 파생된다. 하위 체인 루트 해시는 공식 창세 체인에 앵커링되어, 위로도 아래로도 추적 가능(개인 무료).
- **전문 Merkle 바인딩**: 각 봉인이 전문의 Merkle 루트를 계산하여 체인에 기록하고, 전체 텍스트를 공개하지 않고 원하는 단락을 선택적으로 공개 가능.

**체인 파일 형식(`.rt`)**: ZIP 컨테이너로 `chain.json`(서명 체인)과 `meta.json`(버전·시간·증명서 메타데이터)을 담는다. 체인은 "창작 과정의 증거"만 기록하며 본문은 포함하지 않는다.

자세한 내용은 [`docs/chain-spec.md`](docs/chain-spec.md)와 [`docs/rt-file-format.md`](docs/rt-file-format.md).

## 빠른 시작

### 1. 라이팅 도구를 로컬에서 열기(서버 불필요)

`writer/index.html`을 더블클릭하거나, 아무 정적 서버로 리포지토리 루트를 서빙하세요:

```bash
npx serve .
# http://localhost:3000/writer/ 열기
```

- 작성 전에 "익명 작성" 또는 ".rt 가져와 이어쓰기"를 선택한 후 작성 상자로 이동합니다. 입력하면 자동으로 스탬프가 찍힙니다;
- "봉인·상장"을 클릭해 확정하면 오프라인 검증 페이지로 이동하며, `.txt` 원문과 `.rt` 체인 파일을 다운로드할 수 있습니다(순수 로컬 내보내기, 업로드 없음);
- `verify/index.html`을 열고 `.rt` 파일을 드래그하면 완전 오프라인으로 체인 무결성을 검증할 수 있습니다.

### 2. 공식 창세 체인 앵커링 활성화(선택, 개인 무료)

```bash
copy config.example.js config.js
```

`config.js`를 편집:

```js
window.RT_CONFIG = {
  anchor: {
    apiBase: "https://공식앵커서비스주소",   // 공식 발표 기준
    genesisPublicKey: "공식창세체인루트공개키",
    enabled: true                             // 봉인 시 체인 루트 제출
  }
};
```

> `config.js`는 `.gitignore`로 무시되므로, 자신의 엔드포인트 설정을 실수로 커밋하지 않습니다.
> 개인 창작의 상장은 **무료**; 기업 / 플랫폼 협력은 라이선스 계약(상업 협력은 공식 채널로).

### 3. 테스트 실행

```bash
npm test
```

## 이 버전의 기능(v0.4.0)

이 리포지토리는 **오픈소스 완전 버전**: "작성 → 스탬프 → 봉인 → 검증 → 신원 이어쓰기 → 체인 병합" 완전 루프를 구현한다. 이 버전에는 다음이 포함된다:

- **실시간 스탬프**: 작성 중 Ed25519 서명 스탬프를 자동 생성하고 타자 리듬·멈춤·삭제량 등의 행동 특징을 기록;
- **변조 방지 체인**: 각 스탬프가 바로 앞 스탬프의 체인 해시를 참조하여, 사후 수정은 수학적으로 검출 가능;
- **콘텐츠 미업로드**: 본문은 로컬에만. 체인에는 콘텐츠 해시와 행동 특징만 기록;
- **오프라인 검증**: `.rt` 체인 파일은 서버 의존 없이 완전히 오프라인으로 검증 가능;
- **행동 지문**: 타자 리듬 / 멈춤 / 삭제량 특징(HMAC 행동 체인)으로 신뢰도 분석;
- **창세 체인 앵커링(선택, 개인 무료)**: 봉인 후 체인 루트 해시를 공식 창세 체인에 제출하여 공개 감사 가능한 이력을 형성;
- **버전 추적**: `.rt` 패키지는 `meta.json`에 `appVersion`, `chain.json`에 체인 형식 `version`을 기록하고, 상장 시 버전을 유지.
- **Merkle 선택적 공개**: 각 봉인이 전문 Merkle 루트를 바인딩하여, 전체 텍스트를 공개하지 않고 원하는 단락만 공개 가능;
- **공개 증명 생성**: 오프라인 검증 페이지에서 단락 공개 증명을 원클릭 생성, Merkle 경로 시각화 포함, JSON 복사로 자가 증명;
- **6개 언어 UI**: 작성 페이지 / 오프라인 검증 페이지 / 공식 사이트가 简体中文 · English · 日本語 · 한국어 · Deutsch · Français 지원;
- **체인 ID 명명 규칙**: 공개 키 + 루트 해시를 이중 바인딩한 23자리 체인 ID(`web-personal-…`). 검증 가능, 역산 불가;
- **작성 모드 선택**: 작성 전에 "익명 작성" 또는 ".rt 가져와 이어쓰기" 선택. 이어쓰기는 원래 체인을 자동 연장.
- **타임라인 모듈화**: 확대/축소 가능한 히스토그램 타임라인을 공용 모듈 `core/rt-timeline.js`로 분리하여 작성 리듬을 한눈에 파악 가능.

- **창세 체인 앵커 큐**: 봉인 후 체인 메타데이터를 먼저 로컬 큐에 저장하고, 네트워크 복구 시 자동 재전송. Ed25519 서명(`chainId|rootHash`)으로 위조 방지;
- **앵커 큐 패널(6개 언어)**: 작문 페이지에 ⛓ 상태 표시 / 원클릭 수동 동기화 / 자동 동기화 토글. 콘텐츠 미업로드 유지;
- **개인정보 안내 업데이트**: 봉인 후 체인 메타데이터만 창세 체인에 동기화될 수 있으며, 「⛓」 패널에서 자동 동기화를 끌 수 있음을 명시.

- **신원 모듈**: PBKDF2-SHA256(60만 회) + AES-256-GCM 암호화 신원 키. `.rtkey` 파일 내보내기/가져오기 지원. 신원이 포함된 `.rt`를 가져오면 암호로 작성자 신원을 복구. 봉인 시 암호화된 신원 키를 내장해 같은 키로 원래 체인을 이어 쓸 수 있음;
- **체인 포맷 v3 — 병합 의미론**: 동일 키 이어쓰기는 원래 체인을 자동 연장(`mergeChainsVerified` 재서명 검증). 서로 다른 키는 집계 컨테이너(`aggregateChains`)로 묶어 하위 체인별로 독립 검증;
- **크로스 브라우저 검증기**: tweetnacl 기반 통일 서명 검증. WebCrypto는 폴백으로만 사용해 브라우저 간 결과 일치.

> 전체 변경 기록: [CHANGELOG.md](CHANGELOG.md).

모든 기능은 하위 호환을 유지: 이전 버전이 생성한 `.rt` 체인 파일은 이후 버전에서도 검증·추적 가능해야 한다.

## 사용 시나리오

- **창작자의 투고**: "이거 AI가 쓴 거 아니야?"라는 의심을 받았을 때, `.rt` 현장 증명 하나로 창작 과정을 설명할 수 있다——글자 수, 소요 시간, 창작 리듬, 누구나 검증 가능;
- **저작권 권리 주장**: 입증은 더 이상 말뿐인 주장이 아니다. 체인 위의 행동 지문과 서명 체인이 창작 과정의 감사 가능한 증거를 제공한다;
- **출판사 / 콘텐츠 커뮤니티**: 투고가 정말 인간의 실시간 창작인지, 사후 붙여 넣기나 기계의 일괄 생성이 아닌지 검증;
- **학술 시나리오**: 논문·과제·기술 문서의 창작 과정 증거를 붙여 "내가 썼다"에 근거를 부여한다.

> 창작자는 의심에 맨손으로 맞서지 않아야 한다.

## 프라이버시와 보안

- 기본적으로 **콘텐츠 미업로드**: 작성 내용은 로컬에만. 체인에는 콘텐츠 해시와 행동 특징만 기록;
- `.rt` 체인 파일은 완전히 당신의 통제 아래 있으며, 로컬 보관 또는 자체 암호화 백업 가능;
- 공식 앵커링은 체인 루트 해시와 서명 메타데이터만 제출하며 본문은 제출하지 않는다;
- 모든 검증 로직은 오픈소스이며 직접 감사 가능;
- 보안 취약점을 발견하면 관리자에게 직접 연락하고, 수정 전 공개 공개는 금지.
