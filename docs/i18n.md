# Internationalization Policy

## English is the single source of truth

English is the **authoritative** source for all project files — README, docs, site copy, UI strings, and release notes. Non-English versions are translations derived from the English source.

## Language roles

- **English**: the source of truth; the system abroad runs in full English; GitHub-facing content (repo description, default README, releases, topics, site) is English-primary.
- **简体中文 (zh)**: a Chinese version generated alongside English, for use in the Chinese environment.
- **Other languages**: read/translation convenience only; never authoritative.

## Rules

1. **Content changes are made in the English source first.** Never edit a translation to change product facts, features, links, or version info — those changes belong in the English source.
2. Every translation file starts with an HTML comment pointing to the English source.
3. The language switcher bar and version badges must stay identical across all files.
4. Language codes follow GitHub / Linguist conventions (`zh-TW`, `pt-BR`, ...).
5. The demo media in non-Chinese translations points to the English demo (`realtrace-demo-25s-en.*`); Chinese variants use `-zh`.
6. The system UI abroad is English-only; the Chinese version is used for the Chinese environment; other languages are read-only translations.
7. GitHub-facing content is English-primary: repo description, default `README.md`, release notes, topics, and the site are written in English first; Chinese versions are supplementary.

## How to add or update a README translation

1. Update `README.md` (English).
2. Generate or update `README.<lang>.md` from it — machine translation as a first pass, then a native-speaker review before release.
3. Update the language switcher bar in **all** files (including the new one).
4. Bump the version in all README badges, `package.json`, and `CHANGELOG.md` on release.
