# Realtrace Roadmap · 版本迭代路线

> MVP 最小版先开源引流，按反馈与商业节奏迭代。所有版本保持「向后兼容」：
> 旧版本生成的 `.rt` 链文件在后续版本必须可验证、可追溯。

## 版本与功能矩阵

| 版本 | 技术功能 | 商业定位 |
|:-----|:---------|:---------|
| **v0.1.0（MVP，当前）** | 实时打章、防篡改链、离线验证、`.rt` 文件导出、创世链锚定（个人免费） | 个人免费引流；建立「人类创作认证」品牌信任 |
| **v1.0** | 轻量续写（轻量头 + 增量追加，不上传整链）、链管理（合并 / 拆分 / 分叉检测） | 提高创作连续性，增强用户粘性，为付费能力铺垫 |
| **v1.1** | TSA 时间戳锚定、人脸身份锚定 | 付费分层：Basic 免费 / Plus 司法级时间证明 / Pro 双重锚定 |
| **v2.0** | 零知识验证（snarkjs/circom 电路）、异步密语原语 | 企业级信任门槛与技术壁垒 |
| **v3.0** | 联合授权平台 SDK、支链分发、按链计费、平台水印 / 人脸扩展 | B 端授权收入，平台生态 |

## 版本与链上溯源

- 每个 `.rt` 包内 `meta.json` 记录 `appVersion`，链文件 `chain.json` 记录链格式 `version`；
- 封章上链时携带版本号，任何人可通过链查询到该链「何时、以哪个版本」封章；
- 新增格式时采用「增量兼容」：验证器先读版本号，再按对应规则解析，未知版本拒绝但已存链不受影响。

## 迭代原则

1. **最小闭环优先**：每个版本都先保证「写作 → 打章 → 封章 → 验证」全流程可用；
2. **向后兼容**：核心链格式与签名算法一经发布不再破坏性变更，只能扩展；
3. **隐私底线**：默认零内容上传；任何需要服务端参与的功能必须显式声明；
4. **商业分层**：个人核心能力免费；增值能力（TSA / 人脸 / 联合授权）按版本与授权收费。
